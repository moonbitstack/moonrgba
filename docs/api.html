structColor

pub(all) struct Color

A colour: three components in a named space, and an alpha.

Alpha is kept apart from the components because it is not a colour: it says how much of what is behind shows through, and it survives a change of space untouched.

A component may be none, which CSS writes as the none keyword and which this library carries as a NaN — "this space did not say", which interpolation then fills in from the other side. Ordinary arithmetic on such a component gives NaN back, which is the honest answer.

  • space : Space
  • x : Double
  • y : Double
  • z : Double
  • alpha : Double

Component ranges are the ones the format itself uses, not a common scale: Lab lightness is 0–100 because that is what lab() writes, while Oklab lightness is 0–1 because that is what oklab() writes. A colour out of its space's range is still a valid value — CSS Color 4 lets a colour be outside its gamut and leaves clipping to the moment it is painted.

  • SrgbLinearLinear-light sRGB, components 0–1: sRGB without the transfer curve.

  • HsvHue in degrees, saturation and value 0–1. No CSS syntax of its own.
  • HwbHue in degrees, whiteness and blackness 0–1.
  • LabCIE Lab, D50. Lightness 0–100, a and b roughly ±125.
  • LchCIE LCh, D50: Lab in polar form, hue in degrees.
  • OklabOklab. Lightness 0–1, a and b roughly ±0.4.

enumDelta

pub(all) enum Delta

Which colour difference to measure. The name is the question, not the space: three of these are computed in Lab and one in Oklab.

  • E76CIE76: the Euclidean distance in Lab, which is 1976's answer.
  • E94CIE94, with the graphic-arts weights: 1 for lightness, 1 for chroma, 1 for hue. The textile weights (2, 1, 1) are a different question.
  • E2000CIEDE2000, the current CIE recommendation, with all three weights at 1.
  • OkThe Euclidean distance in Oklab, which needs no weights to be even.

enumLuma

pub(all) enum Luma

Which luma coefficients a YCbCr colour uses.

The three differ only in how much of each primary counts as brightness, and a value converted with the wrong one is visibly off, so the choice is part of the value rather than a global setting.

  • Bt601BT.601: the coefficients of SD television.
  • Bt709BT.709: the coefficients of HD television, and of sRGB in practice.
  • Bt2020BT.2020: the coefficients of UHD television, on wider primaries.

structCmyk

pub(all) struct Cmyk

CMYK for print, as four inks in 0–1.

The conversion is the arithmetic one — full black is all key, and the other three inks spread what is left — not the one an ICC profile for a particular press and paper would give.

Four inks do not fit in three channels, so the arithmetic has to choose: for one colour there are many ink combinations, and to_cmyk returns the one with as much key as possible, which is the usual choice because key ink is cheap and the three colour inks are not. That means a colour survives the round trip but its inks may not: cmyk(0.2 0.4 0.6 0.1) prints the same colour as cmyk(0 0.25 0.5 0.28), and only the second comes back.

  • m : Double
  • y : Double
  • k : Double

A colour as CSS, in the shortest spelling that reads back as the same colour.

Without a format the colour stays in the space it is in, which matters: an OkLCh colour written through sRGB would be clipped to a gamut it never asked for. The spaces CSS cannot spell — HSV, YCbCr — go out as sRGB, and the unresolved currentcolor goes out as itself.

methodColor::name

The name this colour has, if it has one, and the shortest such name where several do: aqua and cyan are the same colour, and four letters beat four letters only by coming first in the table.

A colour that is not one of the 148 opaque names has no name, however close it looks: a name is a spelling, not an approximation.

Gamut

3

Whether a colour fits, and what to do about it when it does not.

Color::in_gamut Color::to_gamut Color::clip

methodColor::in_gamut

pub fn Color::in_gamut(self : Color, space? : Space) -> Bool

Whether the colour is inside the gamut of its space, or of space if one is given.

A space with no gamut answers true: there is nothing for a colour to be outside of.

methodColor::to_gamut

pub fn Color::to_gamut(self : Color, space? : Space) -> Color

The colour brought into the gamut of its space, or of space if one is given, by CSS Color 4's chroma reduction.

A colour already inside comes back unchanged, in the space asked for. One outside loses chroma at constant lightness and hue until it fits, and only in the cases where that cannot work — a colour too light or too dark to exist at all — falls back to clipping.

methodColor::clip

pub fn Color::clip(self : Color, space? : Space) -> Color

The colour with every component clamped into 0–1 of its space, which is what a display does with a colour it cannot show.

Clipping is a blunt instrument: it moves a colour along whichever axis overflows and leaves hue and lightness to follow. to_gamut is the answer that keeps them; this is the answer that costs nothing, and the one to use when the colour is already close to the edge.

Mixing and adjusting

6

color-mix() and the four verbs that move one quantity.

methodColor::mix

pub fn Color::mix( self : Color, other : Color, space? : Space, hue? : Hue, weight? : Double, ) -> Color

A mix of two colours, as color-mix() defines one.

weight is how much of this colour the result has: 0.3 means three parts of this and seven of other, which is what color-mix(in oklab, this 30%, other) writes. It defaults to half.

The result is in the interpolation space, not in the space either colour came from: mixing in Oklab and then converting back to sRGB would lose the out-of-gamut values the mix produced, and to_gamut is the caller's decision to make.

A missing component — none — takes the other colour's value before the mix, so that oklch(none 0.1 200) mixed with a colour that has a lightness interpolates that lightness rather than treating the gap as zero.

currentcolor is not mixed: it stands for a colour nobody has resolved yet, and the result would be a colour that pretends to know.

methodColor::lighten

pub fn Color::lighten(self : Color, amount : Double) -> Color

Move the colour towards white by amount, a fraction of its space's lightness scale: 0.1 in HSL is a tenth of the way to white, 10 in Lab is ten units of lightness.

Hue and chroma are kept, so this is not the same as mixing with white: a mix with white washes the chroma out as well.

methodColor::darken

pub fn Color::darken(self : Color, amount : Double) -> Color

Move the colour towards black by amount, a fraction of its space's lightness scale.

methodColor::saturate

Add chroma, by amount of the space's chroma scale: 0.1 is a tenth of the chroma a colour can have before it leaves what people can see.

Measuring

4

Color::contrast Color::apca Color::luminance Color::delta_e

methodColor::contrast

pub fn Color::contrast(self : Color, other : Color) -> Double

The WCAG 2 contrast ratio between two colours: 1 for the same colour, 21 for black on white.

The order does not matter — this is the measure that is symmetric, and that is one of the reasons APCA exists.

methodColor::apca

pub fn Color::apca(self : Color, background : Color) -> Double

The APCA lightness contrast Lc of this colour as text on background: positive for dark text on a light background, negative the other way round, and zero when the pair is too close to read at all.

The constants are APCA 0.98G-4g, the version the SAPC project publishes for web use. A sign-flipped result is not a mistake: it says which way round the pair is, and the thresholds for readable text are different in each direction, so a caller that wants "is this readable" has to ask about a specific way round.

methodColor::luminance

pub fn Color::luminance(self : Color) -> Double

Relative luminance per WCAG 2: sRGB made linear, weighted by the eye's sensitivity to each primary, with the components clamped to what a screen can show.

methodColor::delta_e

pub fn Color::delta_e(self : Color, other : Color, delta? : Delta) -> Double

The distance between two colours, by the chosen measure.

Colours in any space are converted to the one the measure is defined on, so delta_e answers about the colours, not about where they are written. Opaque alpha plays no part: this is a distance between colours, and a colour at 10% opacity is the same colour as one at 100%.
